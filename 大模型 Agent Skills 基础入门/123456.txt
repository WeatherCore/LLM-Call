你可以直接套用的模板

  下面这个就是 skill-creator-pro 内置的通用创建模板，你按这个格式填好发给我就行：

  帮我创建一个新的 skill。

  我的需求如下：
  - Skill 想解决的问题：
    [用一句话描述那个反复出现的任务]

  - 典型触发场景（至少 3 条）：
    [用户会说什么话时应该触发这个 skill]

  - 明确不该触发的场景（至少 2 条）：
    [看起来像但实际不应该触发的情况]

  - 期望输出：
    [skill 执行完应该产出什么：代码/文档/报告/脚本执行结果...]

  - 是否需要脚本支持：
    [是 / 否 / 由你判断]

  - 是否需要 references（详细参考资料）：
    [是 / 否 / 由你判断]

  - 额外约束：
    [比如：SKILL.md 不能超过多少行；必须有回滚机制；不能依赖外部 API...]

  ---
  举个实际例子

  比如你想做一个「每次写完代码自动帮你做 code review」的 skill，你可以这样写：

  ▎ Skill 想解决的问题： 我写完代码后，总是要手动让 Claude review，想把这个流程标准化。
  ▎
  ▎ 典型触发场景：
  ▎ 1. "帮我 review 刚才的改动"
  ▎ 2. "检查一下这段代码有没有问题"
  ▎ 3. "我这个 commit 有什么风险"
  ▎
  ▎ 不该触发的场景：
  ▎ 1. 只是问我某段代码是什么意思（纯解释，没有 review 意图）
  ▎ 2. 要我写新功能而不是检查已有代码
  ▎
  ▎ 期望输出： 结构化的 review 报告，按严重程度分类
  ▎
  ▎ 是否需要脚本： 由你判断
  ▎ 是否需要 references： 是，需要放常见 bug 模式和修复建议

  ---
  给你几个方向的提示

  如果你还不太确定要做什么 skill，可以沿着这几个方向想：

  1. 你有哪个操作反复做？ — 这很可能值得固化成一个 skill
  2. 你有没有一套"自己做才能放心"的检查流程？ — 交给 skill 来约束
  3. 你平时有没有"每次都忘了某步"的痛点？ — skill 帮你记住
  4. 你有没有一些积累的"模板/配置/规则"？ — 放进 references/ 或 assets/

  ---
  你现在就可以告诉我：你最近有什么重复性的任务，或者你想让 Claude 在什么场景下自动切换到一个特定的工作方式？
  跟我说具体的场景就行，我来帮你把边界确定下来，然后一步步做出 skill。
